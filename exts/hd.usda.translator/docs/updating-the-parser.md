# 현장 태그에 맞게 파서 수정하기

시험 서버의 태그 이름은 HYSYS 엑셀을 기준으로 정했다. 현장 서버를 연결하면 수신기가 저장한 첫 USDA에서 실제 식별자와 값의 구조를 확인한다.

1. `read_snapshot(path)`로 파일을 열고 `snapshot.tags.items()`에서 Endpoint, Namespace URI, 식별자와 샘플의 표시명·단위·자료형을 확인한다. 파일에는 수신기에서 저장 대상으로 고른 태그만 들어 있다.
2. 화면에 필요한 항목 하나를 정해 실제 신호를 찾는다. 한 서버가 HYSYS 계산값과 현장 실측값을 함께 제공하면 `opcua:source`는 양쪽 모두 같은 Endpoint다. 각 신호의 Namespace URI·NodeId·단위를 태그 정의서와 대조하고, 출처나 설비를 식별하기 어려운 항목은 서버 담당자에게 확인한다.
3. [measurements.py](../hd_usda_translator/measurements.py)의 `_interpret_tag()`에서 실제 태그를 대상과 측정 항목에 연결한다. 현재는 태그 하나를 측정값 한 행으로 변환한다. 구조체나 다차원 배열이 `UaBinaryVariantBase64`로 저장돼 있으면 기본 파서는 `Unavailable`을 반환한다. 이 태그가 필요하면 자료형과 필드별 단위를 먼저 확보한다. 여러 필드를 각각의 행으로 제공하려면 변환 함수와 행을 생성하는 `_readings()`, 각 행을 구별할 키까지 함께 정한다. 배지의 기본 선택은 [tags.json](../data/tags.json)에 있다.
4. 실제 USDA에서 대표 항목을 읽고 원문과 파서 출력을 대조한다. 확인할 항목은 측정 지점, 출처, 값, 단위다. 품질이 나쁘거나 수신이 끊겼을 때에는 `value=None`과 해당 `status`가 반환되는지도 확인한다.

시각화 확장이 `("Stream 1", "Pressure")`로 배관을 찾는다면, 태그 주소가 바뀌어도 변환 결과의 `target`과 `quantity`는 그대로 유지한다. 같은 대상·항목에 서로 다른 태그가 있으면 Namespace URI와 식별자로 구분한다. [오버레이와 시각화 확장의 측정값 조회 예제](integration.md)

**작업 요청 예**

> 첨부한 현장 USDA에서 지정한 측정 항목을 읽도록 파서를 수정해 주세요. 출처나 측정 지점이 불분명한 태그는 따로 알려 주세요. 수정 후 대표 항목의 원본 값·단위와 파서 결과를 비교해 주세요.
